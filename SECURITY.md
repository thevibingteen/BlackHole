## 2. Reporting a Vulnerability

We take the security of this project seriously. If you discover a potential security vulnerability, please report it **privately** so it can be evaluated and addressed before public disclosure.

### Private Reporting Channel

* **Email**: [thevibingteen@gmail.com](mailto:thevibingteen@gmail.com)
* **Subject line**: Please format the subject as: `[SECURITY] Vulnerability Report: BlackHole - <Brief Description>`
* **GitHub Private Vulnerability Reporting**: If enabled on the repository, you may alternatively submit an advisory via the [Security Advisories](https://github.com/thevibingteen/BlackHole/security/advisories) tab.

> **Please do not report security vulnerabilities via public GitHub issues, pull requests, discussions, or social media.**

---

## 3. What to Include in a Report

To help us understand and resolve the issue quickly, please provide as much relevant information as possible:

1. **Description**: A clear summary of the vulnerability and its potential security impact.
2. **Affected Components**: Specific source files, classes, methods, or dependencies involved.
3. **Reproduction Steps**: Step-by-step instructions or minimal proof-of-concept code demonstrating the issue.
4. **Environment**: Operating system version (e.g. Android 13/14), application commit SHA or version, device model.
5. **Mitigation**: Any proposed patches, workarounds, or fixes if you have identified them.

---

## 4. Responsible Disclosure Process & Response Expectations

This project is maintained by an open-source community volunteer. While there is no dedicated 24/7 security team or commercial service level agreement (SLA), reports will be handled responsibly as follows:

1. **Acknowledgment**: We will make reasonable efforts to acknowledge receipt of your report within 48 to 72 hours.
2. **Assessment**: The report will be verified and evaluated for impact and feasibility of remediation.
3. **Remediation**: A fix will be developed, tested, and reviewed on a private branch.
4. **Release & Credit**: Once the patch is merged into `main` and released, public credit will be gladly given to the reporter in the release notes (unless anonymity is requested).

We respectfully request that reporters allow a reasonable window of time for coordination and patching prior to disclosing details publicly.

---

## 5. Scope & Exclusions

The following scenarios are generally outside the scope of security advisories for this project:

* Availability, rate-limiting, CAPTCHAs, or blocking imposed by external third-party streaming services (e.g., YouTube, JioSaavn).
* Issues requiring physical access to a rooted, compromised, or jailbroken device.
* Social engineering or phishing targeting community members.
* Attacks requiring specialized physical laboratory equipment or non-standard Android system tampering.
